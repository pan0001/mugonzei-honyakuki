# 付款优惠码

付款优惠码在充值时减价，付款成功后仍发放套餐的全部积分。它可以在有效期内重复使用，也可供多人使用；目前不限制每人使用次数。直接向余额加积分的单次兑换码仍用 `codes` 管理，两种码不能混用。

## 准备真实收款方案

1. 选定一个现有积分套餐、折后价和活动期限。例如，**仅作演示**：200 积分原价 5.00 元，优惠 1.00 元，应付 4.00 元。下列命令用整数分表示金额，400 代表 4.00 元。
2. 在同一爱发电创作者账户下建立独立的、按一个月收取折后价的方案。核对购买页的标价并记下 32 位十六进制 `plan_id`。不能沿用 5 元原价方案，再通过修改付款链接中的金额参数来降价。公开业务套餐配置里继续保留原价方案；折扣方案只绑定优惠活动。
3. 已对外发放付款链接后，保留对应爱发电方案和标价，以便已有订单付款及核验。要改价，使用新的方案和活动码。后台核对爱发电查询返回的订单号、方案和实付金额后才发积分；爱发电通知本身不能增加余额。参见[爱发电开发者文档](https://guide.afdian.com/creator/developer)。

## 创建、查看和停用

日常操作可在[开发者后台](ADMIN.md)完成。登录后打开「优惠码」，选套餐、填折后价和对应爱发电方案，再确认创建。新活动即时生效；下面的本地命令也可用于停服维护。

后台、网站与客户端应先更新到支持优惠码的版本，核对折扣方案后再发码。管理命令仅在服务器本地运行，不通过公网管理。按[维护流程](deploy/README.md)备份并停止占用数据库的服务，使用服务账户、同一个已有数据库（`MUGONZEI_DATABASE`）和同一份常规套餐配置（`MUGONZEI_PLANS_JSON`）；管理完毕立即启动服务。无需把支付密钥传给这些命令。以下参数须替换为实际配置值。

```sh
# 先把两个变量替换为已核对的实际方案
plan_id='本地套餐ID'
discount_plan_id='爱发电折扣方案ID'
dotnet Mugonzei.Server.dll coupons create --plan "$plan_id" --amount-fen 400 --afdian-plan "$discount_plan_id" --days 30
dotnet Mugonzei.Server.dll coupons list

# 需要停止活动时，使用创建或列表命令返回的活动 ID
dotnet Mugonzei.Server.dll coupons revoke --id '活动ID'
```

默认生成随机优惠码。如果需要自选口令，在创建命令末尾追加 `--code-stdin`，启动后输入一行。使用 4–40 个英文字母或数字，可用单个连字符分组，请避开兑换码前缀 `MU`。用户输入时不区分大小写。创建结果仅显示一次完整口令；数据库保存摘要，列表只返回活动信息。有效期默认 30 天，可选 1–365 天。失效或撤销后不能创建新的优惠订单，已按折后价创建的订单仍按原约定核验。

## 购买流程与联调

- 登录后向 `POST /v1/checkout/quote` 提交 `planId` 和 `couponCode`。报价返回 `planId`、`credits`、`originalAmountFen`、`discountFen`、`amountFen`；不产生订单，也不变更余额。
- 用户明确确认后，向 `POST /v1/checkout/orders` 提交同一套餐、优惠码、`expectedAmountFen`（用户确认的应付价）和一个 UUID `requestId`。网络重试须复用原请求编号。后台重新核价；报价不再适用或金额不一致时，不创建订单。
- 客户端核对订单与报价一致才提供付款链接。旧后台没有优惠接口时应提示不支持；不得自动改为原价。用户主动清除优惠码后，可照常走普通购买接口 `POST /v1/orders`。
- 先用本地模拟支付验证报价、重复提交及到账，再小额验证真实爱发电折扣方案。重复通知只能入账一次，订单关联、方案或实付金额不符时不入账。模拟测试不能证明某个真实方案的标价正确。
